# Direction Evidence Extractor

Date: 2026-05-28 KST

## Purpose

This document defines the local extractor that turns a generated `device-evidence.md` report into a structured, non-PII direction evidence summary.

The extractor does not collect hardware evidence, does not update the canonical direction manifest, and does not approve a front/back or four-direction production claim.

## Commands

Extract the current fixture evidence into the default Stage 95 folder:

```bash
scripts/extract-direction-evidence-summary.mjs --json
```

Extract a real phone evidence report after `RUN_PHONE=1` or `scripts/android-device-smoke-test.sh --write-evidence`:

```bash
scripts/extract-direction-evidence-summary.mjs \
  data/runs/20260528_voice_direction_mvp/93-hardware-test-operator-pack/android-phone-smoke/device-evidence.md \
  --report-dir data/runs/20260528_voice_direction_mvp/95-direction-evidence-extractor \
  --json
```

Validate the generated summary:

```bash
scripts/validate-direction-evidence-summary.mjs \
  data/runs/20260528_voice_direction_mvp/95-direction-evidence-extractor/direction-evidence-summary.json \
  --json
```

Strict production-candidate validation:

```bash
scripts/validate-direction-evidence-summary.mjs \
  data/runs/20260528_voice_direction_mvp/95-direction-evidence-extractor/direction-evidence-summary.json \
  --require-production-direction-candidate \
  --json
```

The strict command must fail until controlled non-fixture direction evidence exists.

## Output

Default output folder:

```text
data/runs/20260528_voice_direction_mvp/95-direction-evidence-extractor/
```

Generated files:

- `direction-evidence-summary.json`
- `direction-evidence-summary.md`
- `manifest-update-template.json`

The manifest update template is review input only. Do not copy it into `apps/voice-direction-glass/direction-evidence/manifest.json` by hand.

Use the apply gate instead:

```bash
scripts/apply-direction-evidence-summary.mjs \
  data/runs/20260528_voice_direction_mvp/95-direction-evidence-extractor/direction-evidence-summary.json \
  --json
```

`--write` is allowed only after strict summary validation passes and `productionDirectionCandidate=true`.

## Extracted Fields

The extractor reads only aggregate and diagnostic fields from the evidence report:

- direction sample status, evidence level, direction, confidence bucket, sample rate, and sample count
- microphone inventory captured flag and available microphone counts
- active microphone captured flag, active microphone count, and active channel mapping count
- per-direction front/back/left/right trial counts
- controlled target progress: required trials per direction, required total trials, missing total, per-direction missing counts, and target-complete status
- matched, mismatched, and unknown/unusable counts
- all-direction, front/back, and left/right match rates
- false-direction and unknown/unusable rates
- latency metrics when present
- Bluetooth route probe booleans and counts
- glasses cue seed direction/confidence metadata
- privacy flags proving no raw audio, PCM, transcripts, speaker names, or raw embeddings were persisted

## Promotion Rule

`productionDirectionCandidate` can be true only when all of these are true:

- source evidence is not a fixture
- at least 80 total trials exist
- at least 20 trials exist for each of front, back, left, and right
- controlled target progress is complete with zero missing rows
- all-direction match rate is at least 85%
- front/back match rate is at least 80%
- left/right match rate is at least 90%
- false-direction rate is at most 10%
- unknown/unusable rate is at most 15%
- p95 direction latency is at most 500 ms
- confidence buckets are present
- microphone inventory, active microphones, channel mapping, and mounting/orientation notes are present
- phone controlled evidence is explicitly marked
- at least one wearable route has controlled direction evidence
- privacy flags remain non-PII

## Privacy Guardrail

The summary must not contain command stdout/stderr, logcat dumps, ADB serials, Bluetooth names, MAC addresses, transcripts, speaker names, contact names, exact phrases, raw embeddings, encrypted payloads, PCM, or raw audio bytes.

## Trial/Error Notes

- The fixture has both a repository snapshot and a human-readable direction trial table. The extractor treats the broadcast snapshot as the authoritative automation source because it is generated by the app.
- Fixture evidence can pass default validation, but strict validation must fail.
- p95 latency is required for production direction claims; latest and average latency are not enough.
- Bluetooth route probe success is not the same as controlled wearable direction evidence.
- Target progress is mirrored at the summary root, `aggregateEvaluation.targetProgress`, and `manifestUpdateTemplate.aggregateEvaluation.targetProgress`.
- `controlledTrialTargetComplete=true` is a row-count milestone only; it is not an accuracy claim.
