## Phase 3: Audio Detection Prototype

- Implement trigger phrase detection using Android `SpeechRecognizer`.
- Implement speaker enrollment placeholder using local sample capture.
- Add model interface for speaker verification.
- Use a local/prototype model only after evaluation notes are added.

Current status:

- One-shot `SpeechRecognizer` controller is present and recognized text now runs through event fusion and alert routing.
- Speaker profiles now distinguish development label simulation from future on-device embedding verification.
- The simulated verifier refuses to match profiles that require a real on-device embedding model.
- The host app can capture a short consented voice enrollment sample for a profile, analyze quality in memory, compute a prototype embedding feature vector, and store only averaged embedding reference plus sample count/enrollment state.
- The host app can run a prototype voice match diagnostic by comparing a fresh live sample embedding to the stored profile embedding reference.
- The foreground service can now use the stored prototype embedding reference after a trigger phrase is recognized: it captures one transient post-recognition sample, extracts a prototype live embedding, compares it locally, and emits alerts only when both phrase and prototype voice match pass.
- The foreground service can now try a short stereo direction sample after prototype voice matching. If a real stereo sample is available, the alert uses that estimate; if not, it falls back to the saved prototype direction setting.
- The foreground service now persists the latest automation bridge snapshot, and the host app shows it in a service automation diagnostic card.
- The host app now shows a release readiness card backed by the same checklist used by ADB release readiness snapshots, including the first open phone-alpha evidence states and next actions for hardware testers.
- Manual simulation and foreground service alert routing now use persisted enabled alert channel preferences.
- The host app can run `알림 출력 점검` to emit a generic direction cue through enabled channels without creating a detection event.
- The host app now shows a `방향 큐 계약` card so testers can compare the selected direction's notification text, vibration signature, TTS phrase, and glasses evidence summary before running a physical output test.
- The debug alert-output broadcast now records non-PII cue contract and glasses haptics intent markers so generated device reports can verify the intended output contract without storing full alert text.
- The host app now gates microphone-backed actions behind a `마이크 사용 안내` disclosure; unchecked disclosure blocks OS microphone permission requests and audio flow.
- Sensitive local strings now write through an AndroidKeyStore AES-GCM wrapper instead of plaintext preference values; physical-device migration proof is still needed.
- The domain layer now includes a cosine-similarity `EmbeddingSpeakerVerifier` for future `MODEL_READY` profiles, but the foreground service still needs a live embedding extractor before it can use that verifier.
- Visible Android foreground service is implemented and tied to the session start/stop UI.
- The foreground service now runs a repeated `SpeechRecognizer` listen/evaluate/backoff loop while active.
- Debug alert-output evidence now includes non-PII phone vibration pattern direction, signature, pulse count, total duration, glasses haptics intent metadata, and a flag showing phone vibration is not per-side glasses haptics.
